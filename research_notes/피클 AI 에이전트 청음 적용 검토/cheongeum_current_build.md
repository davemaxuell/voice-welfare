## 1. Task execution on websites (read, navigate, search, autopilot, forms, submit, login, payments, bookings)

### Takeaway
청음 can open any http(s) site, read it in a digested order, follow links by spoken name, go back, search, and run a short LLM "goal" loop (≤10 steps, ≤75 s) that is limited to reading, moving and searching. Form filling is full only on its own local practice form; on real sites it can fill ordinary text fields one by one or in one batch after spoken confirmation, but it never presses submit, never logs in, never handles identity verification, and has no payment or booking capability (those button words are on the block list).

## 2. Voice interaction (STT incl. local whisper, TTS, address word '청음아', barge-in, VAD, progress narration, languages)

### Takeaway
Voice is browser-side capture (VAD loop, barge-in, double-clap, Space, global hotkey) plus server-side STT/TTS providers that are OpenAI, a local in-process faster-whisper model for Korean, a local OpenAI-compatible server, or none (browser speech APIs). There is no always-listening wake word: "청음아" is only stripped from transcribed text. There is no spoken progress narration during long work, and in hands-free mode the microphone is closed while a turn is processing. Four languages (ko/en/zh/ja) are supported through an LLM translation layer.

### Cited Findings
- **STT provider selection.** `create_voice_providers`: `mock`/`browser` → unsupported (browser recognition used); `openai` needs key + `STT_MODEL`; `local` + `STT_BASE_URL` → OpenAI-compatible local server; `local` + `STT_LOCAL_MODEL` → in-process faster-whisper — [voice/config.py · create_voice_providers L38-82](src/cheongeum/voice/config.py). Model IDs come from `.env` only; architecture-check names OpenAI `gpt-4o-mini-transcribe` — [docs/architecture-check.md ① STT row](docs/architecture-check.md).
- **Local whisper.** `LocalWhisperStt` runs faster-whisper (CTranslate2 int8, CPU) in a single-worker thread pool so the event loop is not blocked — [voice/stt_local.py · LocalWhisperStt L25-49](src/cheongeum/voice/stt_local.py). `LanguageRoutedStt`: Korean local, other languages to OpenAI if key + model exist, else local — [config.py · _local_stt L85-105](src/cheongeum/voice/config.py). **Fail-closed:** if faster-whisper or the model is missing, server STT is turned off rather than silently sending Korean audio to OpenAI (same function, L91-98). Model `seastar105/whisper-small-komixv2` at a pinned revision, converted once by script — [scripts/setup_local_models.py L1-40](scripts/setup_local_models.py).
- **Local STT quality (repo-reported).** CPU ≥1.5 s per utterance; on synthetic audio less accurate than OpenAI (command-intent match 79% vs 89%) — [README.md §8](README.md). Another repo review reports local fails 3 of 4 gates for becoming default (CER 12.9% vs 2.5%, digit match 62.5% vs 75%, p95 4.8 s vs 1.8 s) — [agent skills tools - fit for cheongeum.md §8](<drafts/research results/agent skills tools - fit for cheongeum.md>). Pre-commit review verdict: "not ready as-is"; onnxruntime 1.32.0 has no Intel-Mac wheel — [.audit/stt-precommit-check.todo.md](.audit/stt-precommit-check.todo.md). The two sources use different metrics and could not be reconciled because `reports/stt-eval.md` is absent.
- **Browser capture.** `window.SpeechRecognition` for single commands (`interimResults=false`); `MediaRecorder` webm/opus recording — [web/static/mic.js L1-30](src/cheongeum/web/static/mic.js). Hands-free VAD: start threshold `max(0.01, noiseFloor*2.5)`, end after `SILENCE_SHORT_MS=1500` / `SILENCE_LONG_MS=2000` (long if spoken >2.5 s), max utterance cap — [mic.js · VoiceLoop L57-189, L288-289](src/cheongeum/web/static/mic.js).

## 4. Integrations with external services / APIs

### Takeaway
Integrations are limited to: the Korean social-security welfare open APIs (central + local government) with a bundled fixture fallback, one OpenAI-compatible LLM client (OpenAI, Ollama, Qwen/compatible), OpenAI STT/TTS, Naver as default search page, and an optional persistent Google Chrome profile. No OAuth, email, calendar, messaging, or MCP connectors exist, and the repo's own review rejects adding them.

### Cited Findings

- **Fixture data.** Central catalog 461 entries + Busan local catalog + 장애인연금 detail — [README.md §1](README.md); [data/__init__.py · fixture_catalog L314-322](src/cheongeum/agents/welfare/data/__init__.py). ## 5. Proactive features (reminders, suggestions, recurring/scheduled tasks, notifications)

## 6. Personal data and memory (vault, application history, file permissions, encryption)

## 7. Safety and trust

### Takeaway
Safety is layered and mostly deterministic: a single PolicyGuard gate (tiers full / read-only / none, secret-field refusal, risky-button name list, per-turn action cap, approval ids), a network route filter, consent and stop gates with epoch invalidation, PII detection = rules ∪ optional local KoELECTRA model with redaction before any LLM/log use, and rule-based grounding verification of LLM answers. Six concrete gaps (S1–S6) are documented by the repo itself, three of them reproduced, including goal mode pressing the mock submit button without approval on the full-tier site.

### Cited Findings
- **PolicyGuard tiers.** `tier_of`: `full` if origin ∈ `allowedOrigins`; else `read-only` if `readOnlyWeb` and http(s); else `none` — [safety/guard.py · L70-78](src/cheongeum/safety/guard.py). `allowedOrigins` = practice-site origin + `EXTRA_ALLOWED_ORIGINS` only, so **no real public site is full-tier by default** — [server/runtime.py · allowed_origins L182-184](src/cheongeum/server/runtime.py). `READ_ONLY_WEB` defaults true (L110).
- **Checks in order.** Schema → stopped → `maxActionsPerTurn` (12) → action type allowlist → origin tier → (full) secret field id / `SECRET_LABEL` / secret value / field allowlist → risk ≠ low or `requiresConfirmation` needs approval id — [guard.py · check L80-118](src/cheongeum/safety/guard.py); config in [runtime.py L218-227](src/cheongeum/server/runtime.py). Deny codes: `DENIED_SCHEMA, DENIED_STOPPED, DENIED_RATE_LIMIT, DENIED_ACTION_TYPE, DENIED_ORIGIN, DENIED_SECRET, DENIED_FIELD, NEEDS_CONFIRMATION, DENIED_READ_ONLY`.
- **Read-only tier.** Non-search inputs only if `risk == "sensitive"` + `requiresConfirmation` + approved; secret labels/values always denied; clicks only on links or buttons whose name does not match `RISKY_BUTTON`; typing only into search boxes (≤100 chars, no secrets), `press` only Enter — [guard.py · _check_read_only L120-157](src/cheongeum/safety/guard.py). - **Approval flow.** Approvals are action-id based and scoped by `ExecContext.granted(ids)` (added in a `with` block, removed after) — [agents/web/agent.py · L29-35](src/cheongeum/agents/web/agent.py); `_approve` is the only gate that grants for pending assist/submit actions — [session.py L1009-1018](src/cheongeum/orchestrator/session.py). - **Stop / epoch.** Stop words are detected before queuing; `_stop` increments epoch, aborts the controller, clears approvals and dialogue waits — [session.py · handle_turn L159-160, _stop L236-245](src/cheongeum/orchestrator/session.py). - **PII detection/redaction.** Rules: keywords with "strict" handling for 비밀번호/인증번호 (value assumed unless the following words are *about* it), RRN and card patterns, Korean-spoken digit runs ("공일공 일이삼사"), foreign keywords — [safety/privacy.py · KEYWORDS L29-39, VALUE_PATTERNS L41-44, _SPOKEN_RUN L46-49, detect_sensitive L139-162](src/cheongeum/safety/privacy.py). ## 8. What data leaves the machine, to whom, under what condition

### Takeaway
