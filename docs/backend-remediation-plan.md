# Cheongeum backend remediation plan

The first release should let someone ask for documents, decline a login, switch agencies, and interrupt a slow page reliably. The following changes can ship independently. The audit’s identifiers identify the findings each change addresses.

The companion design specifies how the session interprets a public-service request, selects a source, verifies an answer and handles the next spoken turn. [Public-service agent implementation design](public-service-agent-architecture.md)

## What reproduces in this checkout

| Probe | Observed result |
| --- | --- |
| Give the intent parser “정부24에서 로그인은 건너뛰고 주민등록등본 발급 서류만 알려줘” | It returns `LOGIN` followed by `GOAL` with zero planner calls. “로그인은 됐고 국가장학금 서류만 알려줘” returns `LOGIN` alone. These probes measured routing decisions. |
| Interrupt the first simulated Chromium launch and request a browser a second time | Both calls receive the first error. The launch function runs once. |
| Cite a synthetic instruction to visit a 주민센터 and submit a form, then express it as “담당 주민센터에 가서 신청서를 내세요.” | The welfare verifier rejects the paraphrase. An amount question about the same synthetic service takes the rule path with zero model calls. |
| Load desktop configuration with a data directory and no device profile | The profile is `unidentified`, the personal data path is empty, and Chromium uses isolated contexts. API settings and the startup-guide marker have their own storage. |

The browser planner already receives Korea’s current date and recent public-service context. Date-specific answers still need to find the relevant notice and establish which dates it applies to. Saving settings in the UI currently ends the conversation, so an active conversation loses its context. Other open sessions can retain old planner clients. In 0.2.2, microphone input streams through the configured API key to `gpt-live-transcribe`. The orchestrator receives a committed final transcript. Streaming spoken answers and measuring time to first playback are still part of P1-6. ## Delivery order

1. **Start the behavior tests and fix browser recovery and Stop** (P0-5, P0-6, P2-4). Add the probes above to the existing evaluator. After a failed launch or disconnect, discard that specific browser handle and let simultaneous new sessions share one replacement. Mark affected work interrupted and invalidate its approvals. Acknowledge Stop as soon as the local control receives it, cancel the turn, and bound the time spent stopping the renderer. Move local sensitive-data detection and serialized disk writes off the event loop. Keep redaction before a provider call and discard work from a cancelled turn. Test a disconnected browser, a busy privacy worker and a stalled renderer. Measure local Stop acknowledgement separately from microphone transcription and renderer cleanup. [Runtime](../src/cheongeum/server/runtime.py) · [Existing Stop tests](../tests/e2e/test_stop_inflight.py)

2. **Make persistence safe before offering personal-device storage** (P0-4, P0-1). Give the encrypted vault and action log one serialized writer. Use a unique temporary file, flush it, atomically replace the old vault, then publish the in-memory change. Preserve an unreadable original and offer recovery. Commit each action-log entry durably before performing its associated consequential action. Test interruption during a write, a missing key, concurrent sessions, and import of existing files. Add **개인 PC / 공용 PC** to first-run settings. Persist vault data only for a confirmed personal device, isolate shared sessions, and ask existing installations without a recorded choice. A personal browser profile and same-tab reconnection need separate tests. A full app restart must never replay a pending action. [Vault](../src/cheongeum/personal/store.py) · [Action log](../src/cheongeum/personal/action_log.py) · [Recovery contract](../tests/e2e/test_pilot_recovery.py)

3. **Introduce context-aware routing on read-only tasks first** (P1-1, P0-3). Send one structured decision request with the current agency and service, relevant recent turns, explicit exclusions, current page, and any outstanding clarification. Map its result onto existing web and welfare operations. Start with lookup, navigation, repeat and clarify. A read-only request grants only reading and navigation. Keep Stop, consent, authentication handoff and action-specific approval in code. If speech could mean 등본 or 초본, ask one specific question and accept either a correction or a cancellation. During rollout, compare candidate plans against recorded synthetic turns without executing both plans. For authentication, recognize the original tab returning to a known service origin and a usable page. A dashboard may have a new path. Describe it and offer to continue. Resuming a form requires identifying the form again. [Intent precedence](../src/cheongeum/understanding/understand.py) · [Handoff](../src/cheongeum/agents/web/skills/browse.py)

4. **Ground individual welfare claims and improve service lookup** (P0-2, P1-2). Require a source field and exact quote for each spoken claim. For amounts, bind the number to its unit, period and qualifying group. For eligibility, preserve thresholds, negation and exceptions. Render verified facts in plain Korean. When two benefit tiers fit, ask for the distinguishing detail or read both with their conditions. Test a valid paraphrase, swapped tiers, monthly versus annual amounts and a deadline copied from an unrelated field. Paginate the official catalog, separate list and detail cache keys, then index names, aliases and descriptions. An ambiguously named program should produce choices. Verify a match beyond the first 500 records and label dated fallback data. [Welfare verifier](../src/cheongeum/agents/welfare/agent.py) · [Catalog](../src/cheongeum/agents/welfare/data/__init__.py)

5. **Improve provider reliability and time to first audio** (P1-3, P1-4, P1-6). Reuse provider connections, distinguish credential, quota, transient and cancellation errors, and bound retries to operations that can be repeated safely. Apply key and voice changes to the next turn while preserving the current service and independently configured provider credentials. Stream synthesis through to actual desktop playback and cancel buffered audio on Stop. Compare multilingual turns using the same Korean source quotations. Record end-of-speech, final transcript, first spoken answer and interruption latency separately. [Provider client](../src/cheongeum/core/llm.py) · [Desktop playback](../src/cheongeum/web/static/speaker.js)

6. **Expand portal coverage and prepare for field use** (P1-5, P2-1 through P2-4). Read same-origin frames and open shadow roots with stable element identities. Offer the existing masked picture reader for image-only notices, respecting its capture permissions. Connect public-service lookup and place search to the same task. Add local, content-free failure timings, download expiry and indexing, PDF sensitivity checks before upload consent, clear practice-mode reporting, incremental audio hashing and dated dataset refresh including the mobility-center directory. Keep voice powered by the user’s API key. A managed institutional gateway is a separate product decision. Validate the packaged build with NVDA, 센스리더, VoiceOver and participants before drawing accessibility conclusions. [Portal observer](../src/cheongeum/agents/web/browser/observe.js) · [File handling](../src/cheongeum/agents/web/file_answer.py) · [Pilot evaluation](pilot-engineering-results.md)

Run the historical L1.2, L2.3, L4.2 and L6.2 scenarios alongside new paraphrases. Score the requested outcome, agency, source, clarification and actions taken. Include a later launch with quiet startup, explicit guide replay, a scholarship follow-up of “그럼 서류는?”, a switch to 정부24, and “아니요” after a misheard request. Automated portal replays and real assistive-technology sessions answer different test questions.
