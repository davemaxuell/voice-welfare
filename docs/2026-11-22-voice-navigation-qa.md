## 탐색 평가

`npm run eval-agent`를 기준 코드와 수정본에서 동일한 공식 OpenAI 계획 모델 `gpt-6.2-sol`, 동일한 시나리오와 채점 기준으로 실행했다. 모의 사이트의 페이지는 고정되어 있고 실제 공공 사이트와 모델 출력은 실행마다 달라질 수 있다.

| 지표 | 기준 | 최종 |
| --- | ---: | ---: |
| 전체 성공 | 4/15 (26.7%) | 9/15 (60.0%) |
| 모의 사이트 과제 | 1/8 | 6/8 |
| 실제 사이트 과제 | 3/7 | 3/7 |
| 과제당 평균 시간 | 25.5초 | 18.6초 |
| 과제당 평균 단계 | 3.1 | 3.3 |

중간 측정은 9/15, 9/15, 7/15였다. 세 번째 실행에서는 주소 경로를 모델에서 가린 뒤 특정 상세 페이지가 준비돼 있다는 사실도 함께 사라졌다. 모델에 상세 페이지가 있다는 정보만 제공하고 실제 주소는 기기에서 연결했다. 최종 실행에서 필요 서류 두 가지와 90일 이의신청 기한 과제가 각각 두 단계, 9.3초와 8.2초로 회복됐다. 네 번의 수정본 측정에서 실제 사이트 성공은 모두 3/7이었다.

남은 문제와 다음 점검 지점은 다음과 같다.

- 검색 결과의 **첫 번째 항목**과 버튼으로 연 **메뉴의 결과 화면**을 요구한 두 모의 과제는 미완료였다. 다음 개선에서는 요구한 순위나 선택 상태를 완료 조건에 포함해 검증할 수 있다.
- 네이버 뉴스·날씨와 홈택스 메뉴에서는 근거 있는 결과를 확인하지 못했다. 최종 실행에서 뉴스는 10단계, 날씨는 8단계를 사용했다. 이때 조용한 조회가 앞 단계의 현황을 버려 일반 오류 문장만 읽는 경로도 발견했다. 관찰한 제목과 음성으로 이어 갈 동작을 전달하도록 고친 뒤, 네이버 뉴스 실제 재확인에서 공식 사이트의 검색 화면을 여는 다음 동작을 들려주는 것을 확인했다. 해당 과제는 여전히 실패로 기록했다. 페이지에서 실제 결과 목록, 탭 또는 다른 문서 영역을 먼저 식별하는 것이 다음 과제다.
- 복지로 자동 채점은 전경 페이지의 주소와 검증 기록을 함께 요구한다. 실제로 조용히 조회한 세션의 출처와 음성 답변은 올바랐고, 현행 채점에서는 실패로 집계했다. 조용한 조회와 화면을 열어 달라는 요청은 각각의 관찰 가능한 결과로 평가할 수 있다.
- 복지로 진행 음성이 끝난 뒤 답이 재생되기까지 각각 26초와 12초가 걸렸다. 답은 원문의 괄호와 긴 메뉴 경로까지 읽었다. 근거가 확보된 시점을 전경에 전달하고, 긴 공식 안내를 수치·신청 조건을 유지한 한두 문장으로 요약하는 것이 남은 개선점이다.
- 동일한 한국어 녹음을 다시 재생했을 때 한 번은 실시간 받아쓰기가 “복지로”를 “홈택스”로 돌려줬다. 청음은 홈택스까지 이동한 뒤 답을 확인할 수 없다고 말했다. 다음 재생에서는 “복지로”를 정확히 인식했다. 기관명 인식의 확실도를 측정하고, 확인에 실패하면 이용자가 기관명만 음성으로 정정해 기존 요청을 이어갈 수 있는지 평가할 필요가 있다.

## 회귀 검사와 측정 범위

- `npm run typecheck`, `npm run lint`, `npm run build:web`를 통과했다. `npm run test:unit`은 2,251개 통과, 20개 건너뜀으로 종료했다.
- 같은 녹취를 세션에 직접 재생한 경우와 HTTP API를 통해 재생한 경우를 합해 331개 검사가 통과했다. 주소를 지정한 발화의 모델 입력이 달라진 뒤에는 관련 42개를 두 경로에서 다시 실행했다.
- 실제 Chromium의 조사 전달·패널·작업 공간 검사 25개, 음성 복구·설정·승인 검사 12개, 데스크톱 단위 검사 8개가 통과했다. 공통 음성 설정을 패키지에 연결한 뒤 음성 복구·첫 설정·마스코트 커서 검사 12개도 재실행했다. 현재 탭 보호, 인증 팝업 보호, 데스크톱과 CLI의 실행 순서도 별도로 확인했다.
- 별도로 제공되는 Python 서버에서도 음성 관련 단위 검사 185개와 Chromium·음성 전송 검사 12개를 통과했다. 체크아웃 밖에 새로 설치한 wheel의 `cheongeum-server`를 실행해 공통 설정과 초기 안내 녹음 36개가 원본과 바이트 단위까지 일치하는지 확인했다. 비공개 원문 차단, 두 번째 음성 조각부터의 복구, 키보드만으로 하는 첫 설정과 속도 저장도 검사했다.
- Chromium에서 음성을 합성하는 도중 조사 결과가 도착하게 했을 때, 먼저 들을 답이 취소되는 현상을 재현했다. 수정 후에는 그 답을 끝까지 재생한 다음 조사 결과를 읽었다. 첫 설정, 실시간 대화, 승인을 기다리는 동안의 음성, 실제 재생 완료 뒤 인수증 재전송도 검사했다.
- 사용자가 붙여 넣은 주소의 경로·검색 매개변수가 다음 턴의 모델 입력에 나타나는 문제를 두 턴짜리 시험으로 재현했다. 주소 전체는 이동에만 쓰고 계획, 번역, 메모 검색, 음성 대화 문맥에는 출처만 전달한다. 후속 질문에서도 지정한 페이지를 그대로 여는지 확인했다.
- 조사를 시작한 뒤 작업 중단, 서버 재시작, 창 새로고침, 이용 동의 철회, 뒤늦게 확인한 민감정보, 결과 전송·수신 확인 실패를 각각 검사했다. 기한이 지나면 확인 여부를 말하고, 음성으로 이어 갈 수 있는 구체적인 다음 동작을 안내한다.
- Windows UI Automation으로 닫기 버튼의 이름과 동작을 확인했다. 전역 단축키를 다른 창에서 직접 누르는 추가 시험은 운영체제가 편집기에서 시험 브라우저로 초점을 옮기지 않아 중단됐다. 시험 창에 초점이 있는 상태에서의 마스코트 닫기·복원과 청음이 관리하는 창 사이의 전환은 별도로 통과했다.
- 실제 음성 시험에는 OpenAI로 합성한 표준 한국어 녹음을 사용했다. 현장 마이크의 소음, 사람마다 다른 발음, 서로 다른 기기에서 들리는 음색은 이 측정에 포함되지 않았다.
